# HappyRun 风控对策模块 (Anti-Detection)

## 概述

本模块提供策略层逻辑，降低自动化行为被服务端检测的风险。
覆盖两个场景：校园跑 和 俱乐部签到。

---

## 校园跑风控

### 已知服务端检测维度

| 维度 | 检测方式 | 应对 |
|------|----------|------|
| 配速异常 | `boyMaxSpeed=500`, `boyMinSpeed=100`，超出标记 | 控制配速在安全区间 |
| 超速警告 | `runSpeedWarn` 字段，`overSpeedWarn` 提示 | 配速不超过 boyRunSpeed(300) |
| 可疑标记 | `suspectedStatus:"1"` 标记可疑记录 | 轨迹拟真、行为拟真 |
| 围栏检测 | `rangeStatus` 检查是否在校区内 | 确保 >80% 点在围栏内 |
| 重复提交 | `startRun` 触发锁 | 不调用 startRun |
| 轨迹分析 | 对比 trackPoints 与 realityTrackPoints | 保持一致性 |

### 风控策略

1. **配速安全区间**: 200-280 (服务端单位)，对应约 5.5-7.5 min/km
2. **时间窗口**: 只在 06:00-08:00 或 17:00-21:00 提交
3. **频率控制**: 建议每周 3-5 次，不超过学校要求
4. **轨迹真实性**: 沿实际路线、有停顿、有加减速
5. **提交延迟**: trackPoints 最后时间戳与提交时刻间隔 60-180s（真人收尾操作时间）

## 俱乐部签到风控

### 已知检测维度

| 维度 | 检测方式 | 应对 |
|------|----------|------|
| GPS 围栏 | 签到坐标须在活动地点范围内 | 使用 getSignInTf 返回的坐标 + 小偏移 |
| 时间窗口 | 必须在活动时间段内签到 | 严格在 startTime 后才执行 |
| 签退时间 | 不能太快签退（如1分钟就签退） | 延迟 22-28 分钟 |
| 签到频率 | 旷课累计触发惩罚 | 确保已报名活动都签到 |

### 风控策略

1. **坐标偏移**: 基于活动返回坐标 ±10-30m GPS 抖动（不固定同一个点）
2. **签到时机**: 活动开始后 1-5 分钟内签到（不是精确 0 秒）
3. **签退时机**: 活动结束前 0-3 分钟签退（22-28min for 30min活动）
4. **不要秒退**: 签到和签退间隔必须 >20min
